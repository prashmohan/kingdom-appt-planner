## Summary of Additional Findings

Beyond the top 10 critical issues, the following security and hardening improvements were identified:

1. **Docker Container Running as Root**: The [Dockerfile](file:///home/prmohan/projects/kvk-appt/Dockerfile#L1-L11) does not define a non-root `USER`. In production, the container process runs with root privileges. *Recommendation: Add a non-root user (e.g. `useradd -u 1000 appuser`) and set `USER appuser`.*
2. **Missing Rate Limiting on Public Endpoints**: Public routes like `/create` and `/event/<event_uid>/submit` lack rate limiting, allowing automated request flooding, submission spamming, and denial-of-service. *Recommendation: Integrate `Flask-Limiter` to enforce rate limits per IP address.*
3. **Unbounded JSON Import Processing**: In [app/\_\_init\_\_.py](file:///home/prmohan/projects/kvk-appt/app/__init__.py#L920-L1094), `/admin/<event_uid>/import_submissions` executes sequential database deletions and insertions for arbitrarily large uploaded JSON arrays without batching or size limits. *Recommendation: Enforce a maximum submission count per import and use database bulk insert transactions.*
4. **Missing HTTP Security Headers (`Referrer-Policy`, `HSTS`)**: The application does not set `Referrer-Policy: strict-origin-when-cross-origin` or `Strict-Transport-Security` (HSTS). The missing `Referrer-Policy` exacerbates query parameter secret leakage when clicking outbound external links. *Recommendation: Add `Referrer-Policy: no-referrer` and `Strict-Transport-Security` to the `@app.after_request` security headers.*
5. **SQL String Interpolation in Metric Query Builders**: In [app/logic.py](file:///home/prmohan/projects/kvk-appt/app/logic.py#L290-L345), time filter clauses are concatenated into SQL queries using f-strings (`created_at >= datetime('now', '{time_filters[valid_range]}')`). While safe due to dictionary key validation, string interpolation in SQL queries represents an anti-pattern. *Recommendation: Use parameterized SQLite query substitutions.*
